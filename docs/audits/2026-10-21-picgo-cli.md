# PicGo CLI upload audit

Added a fifth, independent `picgo-cli` image storage mode. Existing local, embedded, Cloud and Server modes remain available. The CLI runs only for detection or an image upload; no Server is started. Users install/configure PicGo themselves. Executable paths, not arbitrary shell command strings, are accepted. Windows npm shims resolve to the PicGo package entry and run through Node directly.

Uploads pass a validated assets image snapshot, never the original, with a two-minute timeout, bounded output and HTTPS result validation. Success requires a PicGo success marker and exactly one image URL. Failures retain local assets; no automatic upload retry occurs. A global upload slot avoids concurrent access to shared CLI plugin configuration. Only the exact newly created snapshot is removed during cleanup. Provider credentials and raw CLI output are not returned to the frontend.
