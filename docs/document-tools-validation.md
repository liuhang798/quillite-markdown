# 文档工具与发布安全验证

本批功能纳入 2.7.5 发布。

## 安全约束

- 文档检查只读：代码围栏、标题层级、常见 GFM 表格列数、本应用标题锚点、本地图片存在性。属于基础检查，并非完整 Markdown 标准验证器；无法访问的图片需要人工核对。
- 搜索只读磁盘文本，不扫描代码依赖目录和隐藏目录，不建立持久索引。限制见 README；达到限制时明确标为不完整。
- 替换采用纯文本、区分大小写的规则。预览即固定内容；条件变化需要新预览；服务端只接受预览生成的随机单次令牌及其中的文件，文件选择默认空。
- 每次写入先创建历史版本；原文件变化、删除、链接或写入失败时逐文件报告，不自动重试或回滚已成功文件。不要把多文件批次当作原子事务。
- 恢复检查不会删除快照。另存恢复/历史副本以及诊断报告均拒绝覆盖已有文件。
- 模板存储在本机 WebView 的 localStorage，不同步云端。诊断只导出固定白名单，不包含任意错误文本。

## 本地验证

- `document_commit_test.go`：并发占用最终位置、旧修订、失败恢复后再次保存、新文件竞争；原文、编辑稿和外部版本分别核对，禁止强制回滚覆盖。
- Windows 原文件锁定期间拒绝已有写句柄；保留 ADS 回归。非 Windows 回归验证迟到的文件描述符写入仍有原 inode 恢复文件，不声称能约束不合作的外部编辑器。
- 浏览器回归检查模板预览正文、引用块/HTML/实体标题锚点，以及只读权限提示的实际可点击性。
- 生命周期脚本直接运行安装目录的 `uninstall.exe`，保留生产 `$EXEPATH` 身份校验；实际执行仍只允许临时 GitHub 托管 Windows runner。
- 保存存在短暂的路径交接窗口；进程中断时原文件可能位于文档旁 `.quillite-save-recovery-*` 目录。保留材料优先，不把失败伪装为保存成功。POSIX 成功保存也保留原文件恢复副本，未增加任何自动删除策略。

## 发布环境验证

CI 在封装 Windows 启动器前，用核心安装包执行两次安装（首次安装/原位升级）及一次卸载。测试只允许 GitHub 托管的一次性 Windows runner，创建独立临时目录，校验父目录文档、安装目录文档及多层子目录文件的哈希。测试后保留临时材料供 runner 清理，不对用户路径做递归删除。

该生命周期脚本不等于已经完成跨平台实机认证。本地不会执行它；首次发布需确认对应 CI 步骤成功，并继续人工检查安装界面、快捷方式、文件关联及 macOS/Linux 使用体验。

## 修复后复审结论（2026-09-18）

本轮五项原始问题已有修复和针对性回归。复审发现的普通 Windows 卸载入口阻断已在 2.7.5 修复：注册表 `UninstallString` 明确使用 `_?=$INSTDIR` 从安装目录原位运行，`un.VerifyInstallOwnership` 继续要求 `$EXEPATH == $INSTDIR\uninstall.exe`，没有放宽程序文件、目录标识和登记匹配条件。生命周期 CI 还会核对实际登记字符串，再以相同原位模式执行卸载并验证全部用户文档哈希。
